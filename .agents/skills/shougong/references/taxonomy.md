# 知识树：分类经验与归档 SOP

## 已确认的经验

把知识点平铺在「Agent 算法」「大模型训练」两个筐里，无法表达上下位关系。Agent 工程也不等于 Agent 算法：Pi、DSH 一类 Harness 和 LangChain、LangGraph 一类框架，主要回答系统怎样运行与组织；策略学习、奖励设计和优化算法回答能力怎样形成。具体归属仍看笔记主题，不凭产品名或 Agent 关键词判断。

容量、篇数或现有分类都不能替代概念判断。树表示主要归属，`related` 表示前置、应用和跨领域关联；不能把「有关联」误当成「是其子类」。

## 每次收工的分类步骤

1. **盘点与查重。** 读取完整 taxonomy、已有标题/摘要/别名；对候选父分支及邻近笔记阅读正文，判断新笔记到底解释什么。复学复用概念 ID。
2. **确定技术属性。** 分清系统组件、学习目标、训练方法、优化算法、评测方法等。比如 KL 是分布匹配目标，OPD 是蒸馏方法，Pass@k 是评测指标；不能因为同一 session 提到它们就归到同一层。
3. **检查上下位。** 为笔记选择最具体且语义成立的主分支。兄弟分支的划分维度应尽量一致；综合概述可留在上层，具体专题落在相应子层。为每条路径用一句话说明「它为何属于这里」。
4. **按需重组。** 同一分支出现不同子主题时，建立有独立意义的中间分支，并迁移相关旧笔记，而不只把新笔记归好。主题过宽时拆分，重复分支合并；超出现有领域时增加顶层。不设固定深度或篇数阈值，不用空分类预建百科，也不为每篇笔记制造一个同名父节点。
5. **处理跨界内容。** 按主要解释对象决定归属，用 `related` 连接其他知识。混合笔记优先保留有效正文、稳定 ID 和链接；只有内容已能形成各自完整的学习单元时才拆篇，避免丢失原示例与历史。Agent 工程中的训练应用可以跨链到训练笔记，不必把整篇归为算法。
6. **确认实质歧义。** 如果存在会改变领域边界的多种合理组织方式，先给出具体路径与理由做 QA；用户已确认的分类原则可直接应用，不逐个节点反复确认。
7. **维护历史。** 分类迁移不是再次学习：保留笔记 ID、所有历史日期和 takeaway，不人为增加复学次数。同日新增内容合并日记录，保留先前条目，并让日摘要兼顾已有内容。只改标题或父节点时尽量复用稳定分支 ID。
8. **检查最终树。** 列出受影响路径，确认无孤立笔记、无环、无悬空关联；审查是否仍有混杂平铺或无意义单链。构建后检查深层定位、祖先展开、详情面包屑、跨分支关联和顶层筛选。运行项目规定的校验与 DOM 检查；生成视图不得手工维护。

当前 taxonomy 是可演化的结果，不是新增知识必须服从的固定目录。文档、Skill、工具实现变更单独提交；内容与生成页仍通过专用发布器发布。

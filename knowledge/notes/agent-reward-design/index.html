01

理解概念

回到当时的问题

最终成功但路径奇怪是否该奖励？最终失败但大多数步骤看起来正确是否应该给部分奖励？

分别检查什么

Outcome 检查真实环境终态，而不是 Agent 声称完成。轨迹约束检查过程中是否有禁止操作或副作用。路径少见本身不应扣分；最终成功不能抹掉中途违规。

Process shaping 为中间进展提供反馈，但步骤看起来合理不代表它促进成功。不可接受的行为不宜只用可被高任务分抵消的小罚分，应结合轨迹判不合格与环境权限限制。

边界与未完成问题

长度、关键词、调用次数等代理分数容易鼓励无效行为。Hidden tests、随机化和对抗测试降低部分投机机会，但不保证无漏洞。

本次未深入推导 credit assignment、potential-based shaping 或多奖励权重的数学性质，保留为后续学习。

02

把概念放进示例

01修 bug 时如何分别评分

Agent 修改代码，执行测试，最后报告完成。

  1. 独立验证 bug 修复且没有回归，作为 outcome。
  2. 检查是否删除受保护测试或进行了禁止操作，作为轨迹约束。
  3. 不要因为多跑了几次测试就给进度奖励；确认是否获得有用进展。

得到什么
奇特但合规的成功路径可被奖励；删除测试后的表面成功不能过关；反复测试不自动构成可奖励的进展。

A MOMENT TO RECALL

想一想，再展开答案

不足；还需检查过程中禁止行为及副作用，单纯终态可能遗漏这些问题。

DAPO：从训练问题解释算法改动

相对基础 GRPO，DAPO 针对探索收缩、零优势组、长度权重和截断奖励噪声改善长推理训练。

01

理解概念

回到当时的问题

面试问题：具体项目为什么换成 DAPO，主要改善了什么？本次没有提供真实项目实验结果，不能把机制解释包装成实测经历。

四项改动对应四类问题

Clip-Higher：解耦上下裁剪范围并放宽上界，给正优势下低概率 token 的概率增长更多空间，缓解探索过早收缩。

动态采样：过滤组内奖励相同、优势为零的组并补采有效组。二元正确性奖励下，全对和全错是典型情况；它改善更新 batch 的有效信号比例，但补采会增加 rollout 成本。

Token-level loss：从逐回答平均再聚合改为对 batch 有效 token 统一归一化，调整变长回答的权重，避免长回答每个 token 被长度平均过度稀释。这不等于每个 token 都有独立正确性奖励。

超长奖励塑形：对接近或超过长度限制的输出采用长度相关处理，减轻将“被截断、没答完”直接等同于“推理错误”的奖励噪声。具体软惩罚与过滤设置依实现配置。

项目选择应有证据

先说明实测问题，再说选用的改动。观察熵、组内奖励方差为零的比例、截断率、验证准确率，最好通过消融比较单项贡献。

动态采样不保证整体加速，应比较达到相同能力的总 GPU 小时；DAPO 的优势应结合任务验证，不可从长推理场景直接泛化到所有对话偏好训练。

02

把概念放进示例

01零优势组与有效组

机制演示，不是项目实测：二元奖励下，某 prompt 的候选全对或全错。

  1. 全对组奖励全为 1，全错组全为 0；各自组内中心化后优势均为零。
  2. 动态采样将这些组过滤，并继续采样直到获得足够奖励有差异的组。
  3. 对有效组计算策略梯度，同时统计补采量与 rollout 总耗时。

得到什么
更新 batch 中有用的策略梯度信号增多，但已生成的无效组仍消耗算力，因此有效 batch 改善不等于总时间缩短。

A MOMENT TO RECALL

DAPO 动态采样为什么不保证训练更快？

想一想，再展开答案

补足有效组需要额外 rollout；要比较同等能力下的端到端耗时，而非只看训练 batch 的有效比例。
